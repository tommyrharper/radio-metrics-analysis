# Analysis of Convolutional Resampling Algorithm Performance

**Stable source identifier:** SKA Memo 132
**Authors:** Ben Humphreys, Tim Cornwell (CSIRO Australia Telescope National Facility)
**ADS:** No ADS record was confirmed for this technical memo.
**Full text:** https://openparallel.com/wp-content/uploads/2013/01/tim-cornwell-ben-humphreys-memo132.pdf

## One-line summary
SKA Memo 132 analyzes ASKAP convolutional resampling and benchmarks a W-projection gridder on CPU and GPU hardware, while identifying W-stacking as a memory-for-compute trade-off that can reduce convolution support from more than 100 pixels to about 15 pixels and thereby reduce gridding operations by one to two orders of magnitude.

## Method
The memo models the visibility-to-image path as convolutional resampling of irregular visibility samples onto a regular uv grid followed by an inverse FFT. For wide-field ASKAP imaging, it treats the non-coplanar-baseline w-term through W-projection and also discusses AW-projection, in which the antenna primary beam is included in the convolution function. It defines support as the full width of the two-dimensional convolution region and recommends estimating it from `Theta_FOV * w_rms`, followed by numerical evaluation when more accuracy is required. Its representative support calculation uses an 8 h observation at declination -45 degrees and 1.4 GHz; the reported `lambda w_rms` values are 369 m for the 2 km ASKAP configuration and 480 m for the 6 km configuration, giving effective full-width supports of about 65 and 110 pixels, respectively.

Performance is measured with a standalone version of the ASKAP imager's gridding kernel. The reported benchmark configuration uses 33 W-projection lookup planes, one spectral channel, a 4096 x 4096 pixel output grid, 129-pixel full-width support, and oversampling by 8. CPU tests use the MPI implementation with one grid per core; the CUDA implementation uses one GPU-wide grid, assigns threads to pixels in a convolution region, and processes non-overlapping spectral samples concurrently. The memo also derives an operation and memory-access model for the inner gridding loop and applies the measurements to capacity estimates for ASKAP spectral-line and continuum imaging.

W-stacking is presented as an alternative optimization rather than as a benchmarked implementation. Samples are assigned to the grid for the nearest w-plane; after gridding, each plane receives a separate Fourier transform and w-dependent image-plane phase correction, and the corrected planes are summed. This reduces convolution support and gridding work at the cost of multiple grids, higher memory use, and one FFT per w-plane.

## Performance / fidelity metrics used
- **Convolution-function truncation accuracy:** the operational "Value" rule truncates where the real part first falls below 0.1% of the peak. In the representative W-projection and AW-projection calculations in Figure 3, this retains integrated convolution-function power to within 0.01% of unity. This is a kernel-truncation diagnostic, not an end-to-end image-fidelity measurement.
- **Grid-point throughput (Table 1):** for the 4096 x 4096 grid and 129-pixel support benchmark, the NVIDIA Tesla C2070 CUDA implementation reaches 3413.5 Mpoints/s. Whole-node CPU results are 1408.9 Mpoints/s for a dual-socket Intel Xeon X5570, 393.7 Mpoints/s for a dual-socket Intel Xeon E5462, 372.2 Mpoints/s for a dual-socket AMD Opteron 2218, and 210.9 Mpoints/s for a Blue Gene/P PowerPC 450 node. Figure 4 also shows why per-core scaling is not a valid node estimate: the Intel E5462 falls from 163.25 Mpoints/s on one core to 393.73 Mpoints/s on all eight cores, rather than the approximately 1300 Mpoints/s implied by linear scaling, because the cores share a constrained memory bus.
- **Throughput versus support size (Figure 5):** support sizes from 33 to 257 pixels are tested on the Tesla C2070 and dual-socket Xeon X5570. Throughput rises with support size: small supports are primarily limited by memory latency, while large supports are primarily limited by memory bandwidth. The benchmark was optimized for supports of 65 to 129 pixels, so the authors caution against reading the result as an inherent advantage of large support.
- **Power efficiency (Table 2):** the Xeon X5570 node reports 1408.90 Mpoints/s at an estimated 260 W, or 5.42 Mpoints/s/W; the Tesla C2070 plus host reports 3413.54 Mpoints/s at 390 W, or 8.75 Mpoints/s/W; and the Blue Gene/P node reports 210.88 Mpoints/s at 28 W, or 7.53 Mpoints/s/W. The memo states that these power values come from data sheets, are only accurate to about +/-20%, include interconnect power for Blue Gene/P, exclude cooling, and include the host system for the GPU.
- **Arithmetic intensity and hardware utilization (Section 7):** the complex single-precision inner loop is modeled as 8 floating-point operations and 24 bytes of memory traffic per grid point, approximately 0.3 single-precision flop/byte. The dual-socket Xeon X5570 achieves 11.3 single-precision Gflop/s, 6% of its 187 Gflop/s peak, and just over 50% of the approximately 2600 Mpoints/s bound implied by its nominal 64 GB/s memory bandwidth. The Tesla C2070 achieves 27.3 single-precision Gflop/s, about 2.7% of its 1.03 Tflop/s peak, and about 71% of the approximately 4800 Mpoints/s bound implied by 115.2 GB/s effective bandwidth with ECC enabled.
- **GPU overhead diagnostics (Section 7.2):** at 129-pixel support, fetching 1032 bytes per convolution row through 128-byte cache lines requires nine loads, causing 120 bytes or about 12% overfetch. Gridding 160,000 samples requires 17,417 kernel launches to prevent overlapping convolution regions from being updated concurrently; launch barriers are identified as the secondary bottleneck after memory bandwidth.
- **ASKAP capacity estimates (Table 3):** using the measured dual-socket Xeon X5570 throughput, the 30-arcsec spectral-line pipeline requires 1,156,290 Mpoints/s, about 820 nodes, and 76 double-precision Tflop/s peak; the 10-arcsec spectral-line pipeline requires 4,795,976 Mpoints/s, about 3404 nodes, and 319 double-precision Tflop/s peak; and the continuum pipeline requires 1,498,742 Mpoints/s, about 1063 nodes, and 100 double-precision Tflop/s peak. These are model-based capacity figures for the stated ASKAP configurations, not measured end-to-end pipeline runtimes.
- **Optimization gains (Section 8):** favorable implicit on-the-fly sorting of samples by uvw coordinates improves CPU throughput by about 50% beyond Table 1, while an explicit sort yields 10-20%; software prefetch hints improve throughput by up to 15%, most strongly at small support.
- **W-stacking operation-count estimate (Section 8.3):** relative to ASKAP W-projection supports that can exceed 100 pixels and require tens of thousands of grid-point updates per visibility sample, the memo estimates that W-stacking can use about 15-pixel support and reduce gridding operations by one to two orders of magnitude. It does not report a W-stacking implementation, wall-clock result, memory measurement, image comparison, or end-to-end accuracy benchmark.
- **Image fidelity:** no reconstruction SNR, PSNR, RMSE, dynamic range, residual-image statistic, or deconvolution comparison is reported. The quantitative study concerns computational throughput, power, kernel support and truncation, hardware efficiency, and modeled capacity; image quality is not benchmarked.

## Relevance to visibility→gridding→iFFT→deconvolution ML pipeline
This memo is directly relevant to the gridding and iFFT stages. It supplies concrete baselines for convolution support, grid-point throughput, arithmetic intensity, memory-bandwidth utilization, power efficiency, and end-to-end capacity modeling, and it explains how w-plane partitioning changes the pipeline from one large-support W-projection grid into multiple small-support grids followed by separate inverse FFTs, phase corrections, and summation. For an ML-assisted pipeline, these measurements help prevent a faster learned deconvolver from merely exposing gridding or memory traffic as the next bottleneck. They also motivate evaluating any learned gridding approximation with both systems metrics and separate image-fidelity metrics, since this memo does not establish reconstruction accuracy or deconvolution quality for W-stacking.
