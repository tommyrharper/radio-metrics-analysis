## One-line summary
HVOX evaluates radio-interferometric analysis and synthesis with a chunked three-dimensional type-3 non-uniform FFT, supporting arbitrary spherical pixel meshes such as HEALPix with controllable numerical accuracy and competitive CPU runtime against W-gridding in the tested wide-field and sparse-domain configurations.

## Method
The paper defines analysis as mapping a sky model to predicted visibilities and synthesis as applying the adjoint map to produce a dirty or residual image. HVOX identifies both operations as three-dimensional type-3 non-uniform FFTs: baseline coordinates and sky coordinates can each be non-uniform, so the method is not restricted to a direction-cosine grid. Synthesis spreads non-uniform visibilities onto a uniform three-dimensional grid of spatial harmonics, applies a three-dimensional FFT, interpolates those harmonics at the requested spherical sky coordinates, and corrects the spreading and interpolation windows by tapering. Analysis reverses this adjoint pair.

The intermediate FFT grid is a "Heisenberg mesh." Its dimensions are determined by the products of the baseline-domain and sky-domain bounding-box widths, rather than by the number of output pixels. This decouples FFT size from image resolution and permits direct synthesis onto irregular spherical meshes, including HEALPix, without a separate direction-cosine-to-sphere interpolation.

A monolithic type-3 transform can still demand an impractically large, mostly empty three-dimensional FFT grid when a few long baselines determine the bounding box. HVOX therefore partitions the visibility and sky domains and expresses the full operator as a sum of smaller type-3 transforms. The automatic partitioner uses kd-trees and two-stage agglomerative clustering while constraining each sub-transform's estimated FFT memory and cell anisotropy. Small, sparse sub-problems can fall back to direct evaluation, and independent chunks can be scheduled in parallel. The user can cap per-chunk FFT memory, supply custom partitions, or run chunks sequentially for out-of-core operation.

The released CPU implementation supplies `vis2dirty()` and `dirty2vis()` wrappers for RASCIL and builds the chunked transform with Pycsou, Dask, and the FINUFFT type-3 engine. HVOX v1 is mostly Python and deliberately has no radio-specific optimizations. Because the FINUFFT Python interface did not expose separate spreading, FFT, and interpolation calls, v1 repeats overlapping spread or interpolation work across chunks; this implementation overhead grows with the number of chunks and is not intrinsic to the proposed algorithm.

## Performance / fidelity metrics used
- **Accuracy metric and reference:** The controlled accuracy experiment measures normalized mean square error (NMSE) between visibilities generated by direct evaluation of a point-source sky model and those generated by HVOX, chunked HVOX with a 500 MB per-partition limit, the stable DUCC W-gridder implementation labeled NIFTY, and NIFTY 2D with the w-term omitted. Requested error targets are swept for both direction-cosine and HEALPix source meshes.
- **Direction-cosine-grid accuracy:** Monolithic HVOX follows the requested NMSE down to about 1e-9 in double precision. The paper attributes this floor to FINUFFT's default type-3 upsampling factor of 1.25, which lowers RAM and FFT size but limits accuracy to about nine digits. Chunked HVOX tracks the same curve but slightly misses the requested target because numerical errors accumulate when chunk outputs are summed; the authors propose compensating by tightening each sub-transform's target according to the number of blocks. NIFTY generally exceeds its requested accuracy by about one order of magnitude, while omitting the w-term in NIFTY 2D produces a much larger error that is insensitive to the requested target.
- **HEALPix accuracy and interpolation baseline:** HVOX achieves essentially the same controllable NMSE on HEALPix as on a direction-cosine mesh. NIFTY requires bilinear interpolation from HEALPix to a direction-cosine grid before analysis; that interpolation introduces approximately 1% error, largely independent of the gridder's requested accuracy and comparable in the experiment to omitting the w-term. This comparison isolates the mesh-conversion loss rather than claiming an end-to-end restored-image improvement.
- **Runtime hardware and common setup:** Runtime tests use one workstation with an Intel Core i9-10900X 10-core CPU and 128 GB DDR4 RAM. The default SKA-Low simulation has 251 antennas within a 1 km radius, 94,878 visibilities, one 50 kHz channel centered at 150 MHz, a 30-degree field of view, and a 360 x 360 direction-cosine image with 5.22 arcsec pixels. It samples three evenly spaced time intervals from an 8 h window to emphasize FFT cost, rather than processing every visibility from a full 8 h observation. HVOX uses 20 threads in the monolithic case and 5 per chunk in the chunked case, with a 500 MB maximum partition size.
- **Scaling range and baselines:** Dense and 500-pixel sparse tests vary simulated SKA-Low telescope radius from 0.1 to 100 km, visibility count from 273 to 394,000, and image size from 0.0064 to 182.25 megapixels. Baselines are direct Numba evaluation, monolithic HVOX, HVOX-500MB, the stable DUCC W-gridder, and the same DUCC gridder without w-correction. The paper excludes DUCC's more powerful experimental W-gridder from the comparison.
- **Dense-grid runtime findings:** For dense direction-cosine images, W-gridder is faster than HVOX v1, especially over roughly 1-10 km telescope radii. Monolithic HVOX exhausts memory at the largest configurations, whereas HVOX-500MB continues to the 100 km, 182.25-megapixel case and approaches W-gridder's analysis time there. Synthesis is slower than analysis for the NUFFT methods, with a particularly visible penalty for chunked HVOX because of v1's repeated spreading or interpolation. For dense HEALPix images, W-gridder plus mesh interpolation remains faster in these tests.
- **Sparse-domain runtime findings:** When only 500 sky pixels are requested, HVOX-500MB performs both analysis and synthesis about one order of magnitude faster than W-gridder because it evaluates only the requested regions, while W-gridder still forms the full regular image. HVOX also significantly outperforms W-gridder plus interpolation on sparse HEALPix meshes. These are the paper's strongest runtime results and are relevant to sparse CLEAN models and calibration, but they do not establish the same advantage for dense imaging.
- **Real-data capability and timing:** A qualitative demonstration loads an 8 h LOFAR-HBA Boötes-field measurement set with 24 core and 14 remote stations, synthesizes a 5 x 5 degree dirty image on an approximately 1.5-megapixel HEALPix mesh with HVOX-500MB, and writes FITS output in 38 s on the benchmark workstation. The paper shows the resulting image but reports no source-flux error, residual RMS, PSNR, SSIM, dynamic range, or matched W-gridder timing for this observation.
- **Scope and limitations:** The benchmarks cover only CPU execution. Antenna beam shapes and direction-dependent effects are omitted from the measurement model, and GPU support is future work. A regression over 320 monolithic-HVOX timings projects that removing v1's redundant chunk spreading and interpolation could outperform W-gridder on dense meshes, but this is a modeled implementation target rather than measured HVOX v1 performance.

## Relevance to visibility→gridding→iFFT→deconvolution ML pipeline
HVOX is a classical reference for the visibility-to-grid and Fourier-inversion portion of the pipeline. It replaces a stack of two-dimensional w-plane FFTs with a mesh-agnostic three-dimensional NUFFT whose interpolation step can land directly on HEALPix or another spherical tessellation. Its adjoint analysis operator also supplies the prediction path needed in deconvolution major cycles. The paper's direct-evaluation NMSE, requested-versus-achieved error curves, memory-capped scaling tests, sparse-versus-dense timing split, and complete CPU and workload context provide useful controls for a learned gridder or learned measurement operator.

HVOX does not itself deconvolve an image and does not evaluate reconstruction fidelity after CLEAN or an ML deconvolver. A fair learned-pipeline comparison should therefore test the same analysis and synthesis operators first, report visibility NMSE and operator runtime separately from final-image metrics, preserve whether the target grid is direction-cosine or spherical, and distinguish dense image formation from sparse model prediction. Any end-to-end comparison should add photometric, residual, and restored-image fidelity measures and should not treat the paper's 38 s dirty-image demonstration as a deconvolution benchmark.
